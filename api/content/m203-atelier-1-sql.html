Conception de la base

Cinq tables reliées par des clés étrangères :

clients (id, nom, ville)
   │ 1..n
commandes (id, client_id → clients.id, date_commande)
   │ 1..n                         │ 1..n
details_commandes                 paiements
(id, commande_id → commandes.id,  (id, commande_id → commandes.id,
 produit_id → produits.id,         montant, mode_paiement, date_paiement)
 quantite)
   │ n..1
produits (id, nom_produit, prix_unitaire)
CREATE DATABASE atelier_commerce;
USE atelier_commerce;

CREATE TABLE clients (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nom VARCHAR(50),
  ville VARCHAR(50)
);

CREATE TABLE produits (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nom_produit VARCHAR(50),
  prix_unitaire DECIMAL(10,2)
);

CREATE TABLE commandes (
  id INT AUTO_INCREMENT PRIMARY KEY,
  client_id INT,
  date_commande DATE,
  FOREIGN KEY (client_id) REFERENCES clients(id)
);

CREATE TABLE details_commandes (
  id INT AUTO_INCREMENT PRIMARY KEY,
  commande_id INT,
  produit_id INT,
  quantite INT,
  FOREIGN KEY (commande_id) REFERENCES commandes(id),
  FOREIGN KEY (produit_id) REFERENCES produits(id)
);

CREATE TABLE paiements (
  id INT AUTO_INCREMENT PRIMARY KEY,
  commande_id INT,
  montant DECIMAL(10,2),
  mode_paiement VARCHAR(30),
  date_paiement DATE,
  FOREIGN KEY (commande_id) REFERENCES commandes(id)
);

Requêtes de jointures

-- INNER JOIN : uniquement les lignes qui correspondent dans les 4 tables
SELECT c.nom, cmd.id AS commande, p.nom_produit, dc.quantite
FROM clients c
INNER JOIN commandes cmd ON c.id = cmd.client_id
INNER JOIN details_commandes dc ON cmd.id = dc.commande_id
INNER JOIN produits p ON dc.produit_id = p.id;

-- LEFT JOIN : tous les clients, même sans commande
SELECT c.nom, cmd.id AS num_commande
FROM clients c
LEFT JOIN commandes cmd ON c.id = cmd.client_id;
Jointure Résultat sur Aiven
INNER JOIN 5 lignes : Alice (Ordinateur, Souris, Clavier), Bob (Écran ×2), Charlie (Souris ×3)
LEFT JOIN 5 lignes : Dina apparaît avec NULL, car elle n'a passé aucune commande
RIGHT JOIN 4 lignes : toutes les commandes avec leur client
FULL JOIN MySQL ne le propose pas : simulé avec LEFT JOIN … UNION … RIGHT JOIN

Agrégations et calculs

-- Montant total par commande
SELECT cmd.id AS commande, SUM(p.prix_unitaire * dc.quantite) AS total_commande
FROM commandes cmd
JOIN details_commandes dc ON cmd.id = dc.commande_id
JOIN produits p ON dc.produit_id = p.id
GROUP BY cmd.id;

-- Montant total dépensé par client, seulement au-dessus de 500
SELECT c.nom, SUM(p.prix_unitaire * dc.quantite) AS total_client
FROM clients c
JOIN commandes cmd ON c.id = cmd.client_id
JOIN details_commandes dc ON cmd.id = dc.commande_id
JOIN produits p ON dc.produit_id = p.id
GROUP BY c.nom
HAVING total_client > 500;

-- Prix moyen par produit
SELECT p.nom_produit, AVG(p.prix_unitaire) AS prix_moyen
FROM produits p
GROUP BY p.nom_produit;
  • Totaux par commande : 1 → 990, 2 → 45, 3 → 500, 4 → 60.
  • HAVING total_client > 500 : Alice (1035) seulement. Bob (500) n'est pas strictement supérieur à 500, Charlie (60) non plus.
  • WHERE filtre les lignes avant le regroupement, HAVING filtre les groupes après GROUP BY.

Fonctions SQL : IF(), DATEDIFF() et LIMIT

-- IF() : classer les clients
SELECT c.nom, SUM(p.prix_unitaire * dc.quantite) AS total,
       IF(SUM(p.prix_unitaire * dc.quantite) > 800, 'Premium', 'Standard') AS categorie
FROM clients c
JOIN commandes cmd ON c.id = cmd.client_id
JOIN details_commandes dc ON cmd.id = dc.commande_id
JOIN produits p ON dc.produit_id = p.id
GROUP BY c.nom;

-- DATEDIFF() : délai entre la commande et le paiement
SELECT p.id AS paiement, cmd.id AS commande,
       DATEDIFF(p.date_paiement, cmd.date_commande) AS delai_jours
FROM paiements p
JOIN commandes cmd ON p.commande_id = cmd.id;

-- LIMIT : les 2 meilleurs clients
SELECT c.nom, SUM(p.prix_unitaire * dc.quantite) AS total
FROM clients c
JOIN commandes cmd ON c.id = cmd.client_id
JOIN details_commandes dc ON cmd.id = dc.commande_id
JOIN produits p ON dc.produit_id = p.id
GROUP BY c.nom
ORDER BY total DESC
LIMIT 2;
  • IF() : Alice Premium (1035), Bob et Charlie Standard.
  • DATEDIFF() : paiement 1 → 2 jours, paiement 2 → 1 jour, paiement 3 → 4 jours.
  • LIMIT 2 : Alice (1035) puis Bob (500).

Sous-requêtes : IN, NOT IN et EXISTS

-- Clients ayant au moins une commande payée
SELECT nom FROM clients WHERE id IN (
  SELECT client_id FROM commandes WHERE id IN (
    SELECT commande_id FROM paiements));

-- Clients sans commande payée
SELECT nom FROM clients WHERE id NOT IN (
  SELECT client_id FROM commandes WHERE id IN (
    SELECT commande_id FROM paiements));

-- Même résultat que IN avec une sous-requête corrélée
SELECT nom FROM clients c
WHERE EXISTS (
  SELECT 1 FROM commandes cmd
  JOIN paiements p ON cmd.id = p.commande_id
  WHERE cmd.client_id = c.id);
  • IN et EXISTS : Alice, Bob.
  • NOT IN : Charlie (commande non payée) et Dina (aucune commande).

Optimisation : index et vues

EXPLAIN SELECT * FROM produits WHERE nom_produit = 'Souris';   -- avant

CREATE INDEX idx_nom_produit ON produits(nom_produit);
CREATE INDEX idx_client_ville ON clients(ville);

EXPLAIN SELECT * FROM produits WHERE nom_produit = 'Souris';   -- après
EXPLAIN type key rows filtered
Avant l'index ALL (parcours complet de la table) NULL 2 50 %
Après l'index ref (accès direct par l'index) idx_nom_produit 1 100 %

MySQL ne lit plus toute la table : il va directement à la ligne « Souris » grâce à l'index B-Tree.

CREATE VIEW vue_ventes AS
SELECT c.nom, p.nom_produit, dc.quantite,
       (p.prix_unitaire * dc.quantite) AS montant, pa.mode_paiement
FROM clients c
JOIN commandes cmd ON c.id = cmd.client_id
JOIN details_commandes dc ON cmd.id = dc.commande_id
JOIN produits p ON dc.produit_id = p.id
LEFT JOIN paiements pa ON cmd.id = pa.commande_id;

SELECT * FROM vue_ventes;
SELECT * FROM vue_ventes WHERE montant > 200;

La vue renvoie les 5 ventes. Charlie a mode_paiement = NULL, car sa commande n'est pas payée (LEFT JOIN). Le filtre montant > 200 garde Alice, Ordinateur (950) et Bob, Écran (500).

DCL : gestion des utilisateurs

CREATE USER 'vendeur'@'localhost' IDENTIFIED BY '1234';
CREATE USER 'manager'@'localhost' IDENTIFIED BY 'admin';

GRANT SELECT, INSERT, UPDATE ON atelier_commerce.* TO 'vendeur'@'localhost';
GRANT ALL PRIVILEGES ON atelier_commerce.* TO 'manager'@'localhost';
FLUSH PRIVILEGES;

SHOW GRANTS FOR 'manager'@'localhost';

REVOKE UPDATE ON atelier_commerce.* FROM 'vendeur'@'localhost';
  • vendeur : SELECT, INSERT, UPDATE, puis seulement SELECT, INSERT après le REVOKE UPDATE.
  • manager : ALL PRIVILEGES sur atelier_commerce.*.
  • Principe du moindre privilège : chaque utilisateur reçoit uniquement les droits dont il a besoin. Les mots de passe 1234 et admin sont ceux de l'énoncé : en production, il faudrait des mots de passe forts.
