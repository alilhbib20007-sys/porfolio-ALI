Contexte et objectifs

Le centre de formation TechLearn propose des sessions animées par des formateurs. Chaque session a un formateur, une capacité maximale et un nombre d'inscrits. L'administration veut automatiser :

  • le calcul du taux d'occupation des sessions ;
  • la mise à jour du nombre d'inscrits ;
  • la suppression des sessions vides ;
  • la génération de rapports.

Objectifs pédagogiques : créer des procédures et des fonctions stockées, utiliser les paramètres IN, OUT et INOUT, et les structures de contrôle (IF, WHILE).

Création de la base et insertion

CREATE DATABASE techlearn_db;
USE techlearn_db;

CREATE TABLE formateurs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100),
    specialite VARCHAR(100)
);

CREATE TABLE stagiaires (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100),
    ville VARCHAR(100)
);

CREATE TABLE sessions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    intitule VARCHAR(100),
    formateur_id INT,
    capacite INT,
    inscrits INT DEFAULT 0,
    FOREIGN KEY (formateur_id) REFERENCES formateurs(id)
);

Exercices 1 à 3 : IN, OUT et INOUT

DELIMITER //
-- Exercice 1 : IN
CREATE PROCEDURE afficher_stagiaires_par_ville(IN ville_nom VARCHAR(100))
BEGIN
    SELECT * FROM stagiaires WHERE ville = ville_nom;
END //

-- Exercice 2 : OUT
CREATE PROCEDURE compter_sessions(OUT total INT)
BEGIN
    SELECT COUNT(*) INTO total FROM sessions;
END //

-- Exercice 3 : INOUT
CREATE PROCEDURE inscrire_stagiaire(INOUT nb_inscrits INT, IN session_id INT)
BEGIN
    UPDATE sessions SET inscrits = inscrits + 1 WHERE id = session_id;
    SELECT inscrits INTO nb_inscrits FROM sessions WHERE id = session_id;
END //
DELIMITER ;

CALL afficher_stagiaires_par_ville('Casablanca');

CALL compter_sessions(@nb);
SELECT @nb AS nombre_total_sessions;

SET @nouveau = 0;
CALL inscrire_stagiaire(@nouveau, 1);
SELECT @nouveau AS nouveau_nombre_inscrits;

Exercices 4 et 5 : fonction et boucle

DELIMITER //
CREATE FUNCTION taux_occupation(id_session INT)
RETURNS DECIMAL(5,2)
READS SQL DATA
BEGIN
    DECLARE taux DECIMAL(5,2);
    SELECT (inscrits / capacite) * 100 INTO taux FROM sessions WHERE id = id_session;
    RETURN taux;
END //

CREATE PROCEDURE generer_sessions(IN formateur INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    WHILE i <= 10 DO
        INSERT INTO sessions (intitule, formateur_id, capacite, inscrits)
        VALUES (CONCAT('Session ', i, ' - Formateur ', formateur), formateur, 20, 0);
        SET i = i + 1;
    END WHILE;
END //
DELIMITER ;

SELECT intitule, taux_occupation(id) AS taux FROM sessions;
CALL generer_sessions(2);

Défis finaux 1 et 2

DELIMITER //
-- Défi 1 : nombre de sessions d'un formateur, à partir de son nom
CREATE FUNCTION sessions_formateur(nom_formateur VARCHAR(100))
RETURNS INT
READS SQL DATA
BEGIN
    DECLARE nb INT;
    SELECT COUNT(*) INTO nb
    FROM sessions s
    JOIN formateurs f ON f.id = s.formateur_id
    WHERE f.nom = nom_formateur;
    RETURN nb;
END //

-- Défi 2 : supprimer les sessions sans inscrits
CREATE PROCEDURE supprimer_sessions_vides()
BEGIN
    DECLARE nb INT;
    SELECT COUNT(*) INTO nb FROM sessions WHERE inscrits = 0;
    DELETE FROM sessions WHERE inscrits = 0;
    SELECT CONCAT(nb, ' session(s) vide(s) supprimée(s)') AS resultat;
END //
DELIMITER ;

SELECT nom, sessions_formateur(nom) AS nb_sessions FROM formateurs;
CALL supprimer_sessions_vides();

  • supprimer_sessions_vides() : 10 sessions vides supprimées. Il reste les 3 sessions d'origine.

Défi 3 : valider_inscription

DELIMITER //
CREATE PROCEDURE valider_inscription(IN session_id INT)
BEGIN
    DECLARE v_inscrits INT;
    DECLARE v_capacite INT;
    SELECT inscrits, capacite INTO v_inscrits, v_capacite
    FROM sessions WHERE id = session_id;
    IF v_inscrits >= v_capacite THEN
        SELECT 'Session complète' AS message, v_inscrits AS inscrits, v_capacite AS capacite;
    ELSE
        UPDATE sessions SET inscrits = inscrits + 1 WHERE id = session_id;
        SELECT 'Inscription validée' AS message, v_inscrits + 1 AS inscrits, v_capacite AS capacite;
    END IF;
END //
DELIMITER ;

CALL valider_inscription(2);                        -- 10/25 : place libre
UPDATE sessions SET inscrits = capacite WHERE id = 3;
CALL valider_inscription(3);                        -- 15/15 : pleine

Les deux cas du IF sont testés :

  • HTML/CSS (10/25) : « Inscription validée », les inscrits passent à 11.
  • Python Data, remplie à 15/15 pour le test : « Session complète », rien n'est modifié.

Taux final : 30 %, 44 % et 100 %. La base contient 6 procédures et 2 fonctions.

Conclusion

Cet atelier m'a montré l'intérêt de placer la logique métier dans la base : une règle comme « pas d'inscription si la session est pleine » est écrite une seule fois, dans valider_inscription, et tout programme qui appelle cette procédure la respecte.

J'ai bien compris la différence entre :

  • une fonction, qui retourne une valeur et s'utilise dans un SELECT (taux_occupation) ;
  • une procédure, qui agit sur les données et renvoie des valeurs par OUT ou INOUT (inscrire_stagiaire).

L'exécution sur un serveur distant m'a aussi appris deux contraintes réelles :

  • le choix du délimiteur (//), à cause de la division / ;
  • la déclaration READS SQL DATA exigée par MySQL quand le journal binaire est actif.
